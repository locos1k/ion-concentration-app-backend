# ion-concentration-app-backend

Бэкенд для лабораторных по РИП. Тема — растворы электролитов (кислоты, щёлочи, соли):
их можно листать лентой, добавлять и публиковать, искать по молярной концентрации,
ставить лайки и удалять.

Стек: **NestJS** + **Handlebars** для страниц (ЛР1–2), **REST API** с JSON (ЛР3),
**PostgreSQL** (через **TypeORM**) — основное хранилище, **MinIO** — для фото и видео.

## Запуск

```bash
npm install
cp .env.example .env                           # параметры подключения
docker compose up -d postgres adminer minio   # БД, админка и хранилище файлов
npm run migrate                                # создать таблицы (один раз)
npm run start:dev
```

Приложение поднимется на `http://localhost:3000`. Страницы — `/solutions`, API — `/api/...`.
Adminer — на `http://localhost:8081`, консоль MinIO — на `http://localhost:9001`.

Бакет `solution-assets` в MinIO должен существовать и быть открыт на чтение
(anonymous access: readonly), иначе картинки и видео по ссылкам не откроются.

Тестовые данные — `scripts/seed.sql` (вставить через Adminer или `psql`). Скрипт сначала
очищает таблицы, поэтому повторный запуск безопасен. В нём 4 пользователя (`student`,
`anna`, `boris`, `olga`), 8 растворов во всех статусах и лайки от разных пользователей.

## Что где лежит

- `src/solutions/` — растворы: контроллеры (страницы и API), сервис, entity, DTO
- `src/solutions/dto/` — входные DTO с валидацией и сериализатор ответа (`solution-response.dto.ts`)
- `src/solutions/solution-media.service.ts` — загрузка файлов в MinIO
- `src/users/` — пользователи: регистрация, заглушки входа/выхода, функция-singleton текущего пользователя
- `views/`, `public/` — шаблоны и статика страниц из ЛР1–2
- `scripts/migrate.ts` — создаёт таблицы по entity, `scripts/seed.sql` — тестовые данные
- `docker-compose.yml` — PostgreSQL, Adminer и MinIO

## Текущий пользователь (функция-singleton)

Авторизации пока нет (она будет в ЛР4), поэтому «создатель» во всех методах — константа,
которую возвращает функция-singleton `getCurrentUser()` в
[`src/users/current-user.ts`](src/users/current-user.ts): пользователь `student` с `id = 1`.
Объект создаётся один раз при первом вызове, дальше возвращается тот же (и заморожен
через `Object.freeze`).

Функция используется в `src/solutions/solutions.service.ts` (черновик пользователя,
создатель нового раствора, проверка владельца при публикации и удалении, лайк) и в
`src/solutions/solutions-api.controller.ts` (признаки `isLiked` и `isCreator` в ответе).
В ЛР4 достаточно заменить тело этой функции на получение пользователя из сессии.

## REST API

Все адреса начинаются с `/api`. Данные — JSON, кроме создания раствора
(`multipart/form-data`). Системные поля (id, статус, создатель, даты) с клиента не
принимаются: лишнее поле в теле запроса даёт `400`. Раствор в статусе `deleted` клиенту
не отдаётся.

### Домен растворов

| № | Метод | URL | Описание | Входные данные | Выходные данные |
|---|---|---|---|---|---|
| 1 | GET | `/api/solutions` | Список опубликованных растворов с фильтром по молярной концентрации | query: `min?: number`, `max?: number` (оба необязательные, ≥ 0) | `200`, массив растворов (поля ниже) |
| 2 | GET | `/api/solutions/feed` и `/api/solutions/feed/:id` | Лента опубликованных. Без `id` — первый раствор. С `id` — этот раствор, а с `next=true` — следующий за ним (после последнего снова первый) | path: `id?: number`; query: `next?: boolean` | `200`, один раствор; `404`, если раствор не найден или не опубликован |
| 3 | GET | `/api/solutions/draft` | Черновик текущего пользователя (не больше одного, `id` не указывается) | — | `200`, раствор со статусом `draft`; `404`, если черновика нет |
| 4 | POST | `/api/solutions` | Создание черновика с файлами. Файлы уходят в MinIO под сгенерированными латинскими именами, в БД сохраняются только ключи | `multipart/form-data`: `substanceName: string` (1–70 символов), `image: file` (jpeg, png, webp, gif), `video: file` (mp4, mov, webm) | `201`, созданный раствор; `400` — нет файла, неверный тип или поле; `409` — черновик у пользователя уже есть |
| 5 | PUT | `/api/solutions/:id/publish` | Публикация черновика: смена статуса `draft` → `published` и заполнение полей | path: `id: number`; JSON: `description: string` (≤ 500), `molarConcentration: number` (0–99.999, до 3 знаков), `ph: number` (0–14, до 2 знаков) | `200`, опубликованный раствор; `403` — чужой раствор; `404` — не найден или удалён; `409` — раствор не черновик |
| 6 | DELETE | `/api/solutions/:id` | Мягкое удаление (статус `deleted`), только своих растворов | path: `id: number` | `204`, без тела; `403` — чужой; `404` — не найден или уже удалён |
| 7 | POST | `/api/solutions/:id/like` | Поставить или отменить лайк от текущего пользователя. Повторный запрос ничего не меняет | path: `id: number`; JSON: `value: 0 \| 1` (`1` — поставить, `0` — отменить) | `200`, раствор с обновлённым `likesCount`; `404` — раствор не опубликован |

Раствор в ответах (`SolutionResponseDto`):

| Поле | Тип | Описание |
|---|---|---|
| `id` | number | идентификатор |
| `substanceName` | string | название вещества |
| `description` | string | описание (у черновика пустая строка) |
| `molarConcentration` | number \| null | молярная концентрация, моль/л |
| `ph` | number \| null | водородный показатель |
| `imageUrl`, `videoUrl` | string | ссылки на файлы в MinIO (или на файлы по умолчанию, если ключ пуст) |
| `likesCount` | number | число лайков |
| `isLiked` | boolean | текущий пользователь поставил лайк |
| `isCreator` | 0 \| 1 | текущий пользователь — создатель раствора |
| `status` | `draft` \| `published` \| `deleted` | статус |

Статусы нельзя менять с любого на любой: `draft` → `published` или `deleted`,
`published` → `deleted`, из `deleted` переходов нет (таблица `ALLOWED_TRANSITIONS` в
`src/solutions/solutions.service.ts`). Вернуть раствор в черновик нельзя.

### Домен пользователей

| № | Метод | URL | Описание | Входные данные | Выходные данные |
|---|---|---|---|---|---|
| 8 | POST | `/api/users` | Регистрация. Пароль хранится в виде `соль:хеш` (scrypt) | JSON: `username: string` (3–50), `password: string` (6–72) | `201`, `{ id, username }`; `409` — логин занят; `400` — неверные поля |
| 9 | POST | `/api/auth/login` | Аутентификация (заглушка, настоящая — в ЛР4) | JSON: `username: string`, `password: string` | `200`, `{ message, user: { id, username } }` — текущий пользователь из singleton |
| 10 | POST | `/api/auth/logout` | Деавторизация (заглушка, настоящая — в ЛР4) | — | `200`, `{ message }` |

## База данных

Три таблицы (ER-диаграмма и диаграмма классов — в StarUML). Каскадного удаления нет.

**`solutions`** — растворы

| Колонка | Тип | Описание |
|---|---|---|
| `solution_id` | integer, PK | идентификатор |
| `name` | varchar(70) | название вещества |
| `molar_concentration` | numeric(5,3), null | молярная концентрация, моль/л (заполняется при публикации) |
| `ph` | numeric(4,2), null | водородный показатель (заполняется при публикации) |
| `description` | varchar(500), null | краткое описание |
| `image` | varchar(255) | ключ изображения в MinIO (пусто — файл по умолчанию) |
| `video` | varchar(255) | ключ видео в MinIO (пусто — файл по умолчанию) |
| `status` | varchar(10) | `draft` / `published` / `deleted` |
| `created_at` | timestamp | дата создания |
| `published_at` | timestamp, null | дата публикации |
| `creator_id` | integer, FK → `users.user_id` | создатель |

**`users`** — пользователи

| Колонка | Тип | Описание |
|---|---|---|
| `user_id` | integer, PK | идентификатор |
| `username` | varchar(50), unique | логин |
| `password` | varchar(255) | хеш пароля |

**`likes`** — лайки (связь «многие ко многим» между пользователями и растворами)

| Колонка | Тип | Описание |
|---|---|---|
| `like_id` | integer, PK | идентификатор |
| `user_id` | integer, FK → `users.user_id` | кто поставил |
| `solution_id` | integer, FK → `solutions.solution_id` | какому раствору |

У каждого пользователя не больше одного раствора в статусе `draft`.

## Страницы (ЛР1–2)

Все адреса начинаются с `/solutions`:

- **`/solutions`** и **`/solutions/:id?next=true`** — лента опубликованных растворов
- **`/solutions/draft`** — добавление: форма с названием, затем форма публикации
- **`/solutions/list?min=&max=`** — каталог с фильтром по молярной концентрации и
  кнопкой логического удаления (сырой SQL `UPDATE`)

Эти страницы сделаны по условиям ЛР2: файлы из формы на сервер не отправляются, у новых
черновиков показываются фото и видео по умолчанию из `public/img`. Загрузка настоящих
файлов в MinIO работает через API (`POST /api/solutions`).

## MinIO

Бакет `solution-assets` (порт 9000, консоль — 9001). Адрес для ссылок задаётся
переменной `MEDIA_BASE_URL`, параметры подключения — переменными `MINIO_*`
(значения по умолчанию совпадают с `docker-compose.yml`, см. `.env.example`). Имена
загруженных файлов генерируются на латинице: `solution-image-<uuid>.<расширение>` и
`solution-video-<uuid>.<расширение>`.
