# ion-concentration-app-backend

Бэкенд для лабораторной по РИП. Тема — растворы электролитов (кислоты, щёлочи, соли):
их можно листать лентой, добавлять и публиковать через форму, искать в каталоге по
молярной концентрации и удалять.

Стек: **NestJS** + **Handlebars** для шаблонов, **PostgreSQL** (через **TypeORM**) —
основное хранилище, **MinIO** — для фото и видео. Никакого JavaScript на страницах —
всё на HTML и CSS, даже создание и публикация растворов идут через обычные формы.

## Запуск

```bash
npm install
docker compose up -d postgres adminer minio   # БД, админка и хранилище файлов
npm run migrate                                # создать таблицы (один раз)
npm run start:dev
```

Приложение поднимется на `http://localhost:3000` и сразу перекинет на `/solutions`.
Adminer — на `http://localhost:8081` (параметры подключения см. в `.env.example`).

Чтобы наполнить БД тестовыми данными — вставьте `scripts/seed.sql` через Adminer
(SQL command) или `psql`. Скрипт идемпотентный: каждый раз сначала чистит таблицы,
потом наполняет заново, так что вставлять его повторно безопасно.

## Что где лежит

- `src/solutions/` — вся логика: контроллер с роутами, сервис, entity для трёх таблиц БД
- `views/` — три Handlebars-шаблона (лента, добавление, каталог) + общие куски в `views/partials`
- `public/` — CSS и статические картинки/видео (в т.ч. дефолтные фото/видео)
- `docker-compose.yml` — PostgreSQL, Adminer и MinIO
- `scripts/migrate.ts` — создаёт таблицы по entity, `scripts/seed.sql` — наполняет тестовыми данными

## Страницы

Все адреса начинаются с `/solutions`:

- **`/solutions`** и **`/solutions/:id?next=true`** — лента опубликованных растворов
- **`/solutions/draft`** — добавление: сначала форма с одним полем (название), после
  создания черновика — форма с остальными полями и публикацией
- **`/solutions/list?min=&max=`** — каталог с фильтром по молярной концентрации
  (двойной ползунок) и кнопкой логического удаления на каждой карточке

Раствор в статусе `draft` виден только на странице добавления, `deleted` — нигде.

## База данных

Три таблицы (ER-диаграмма — в StarUML): `solutions` (растворы), `users`
(пользователи) и `likes` (лайки, м-м между пользователями и растворами). Все GET-запросы,
создание и публикация раствора — через TypeORM; логическое удаление — отдельным
сырым SQL-запросом (`UPDATE ... SET status = 'deleted'`).

## MinIO

Фото и видео уже опубликованных растворов берутся из бакета `solution-assets`
(порт 9000, консоль — 9001, адрес бакета настраивается переменной `MEDIA_BASE_URL`).
У новых черновиков файлы пока не сохраняются — вместо них показываются дефолтные
фото/видео из `public/img`.
