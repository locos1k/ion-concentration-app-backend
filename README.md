# ion-concentration-app-backend

Заявочная система по предметной области **«Концентрация ионов в растворах электролитов»**.
Лабораторная работа №1 (РИП): бэкенд на NestJS + шаблонизатор Handlebars, три страницы
приложения в портретном (мобильном) режиме, данные — из одной модели-коллекции в памяти,
без БД и без JavaScript.

## Стек

- **NestJS 12** (TypeScript, ESM)
- **Handlebars** (`hbs`) как view engine
- статика (`CSS`, изображения) из `public/`
- медиа услуг — ключами на латинице, хранилище **MinIO** (пока не поднят — см. ниже)

## Предметная область

Одна сущность — **раствор электролита** (`Solution`). Поля по теме:

| Поле | Назначение |
|------|-----------|
| `substanceName` | название вещества («Соляная кислота») |
| `chemicalFormula` | химическая формула (`HCl`) |
| `electrolyteType` | тип электролита: кислота / основание / соль |
| `molarConcentration` | молярная концентрация, моль/л — **числовое поле, по нему фильтр** |
| `description` | текстовое описание (диссоциация и т.п.) |
| `volumeMl` | объём раствора, мл |
| `image` / `video` | ключи файлов в MinIO на латинице (`hcl.svg`, `hcl.mp4`) |
| `likedBy` | список id пользователей (атомарно, 1НФ) |
| `status` | `draft` / `published` / `deleted` |

В коллекции есть один раствор в статусе `draft` (Аммиак) — он показывается на странице
«Добавление», и один `deleted` (Уксусная кислота) — он нигде не отображается.

## Страницы и роутинг (3 GET-запроса)

| URL | Контроллер-метод | Шаблон | Что делает |
|-----|------------------|--------|-----------|
| `GET /` и `GET /:id?next=true` | `SolutionsController.getFeed` | `feed.hbs` | Лента. Без `id` — первый опубликованный раствор. С `id` — конкретный; с `?next=true` — следующий за ним по кругу. |
| `GET /draft` | `SolutionsController.getDraftPage` | `add.hbs` | Страница «Добавление» с данными единственного черновика. Поля можно менять, сохранения нет (POST — задача ЛР2). |
| `GET /list?filter=<число>` | `SolutionsController.getGrid` | `grid.hbs` | «Плитка»: все опубликованные растворы в 2 столбца. Фильтр по молярной концентрации **на сервере**, значение возвращается в поле ввода. |

Нижняя панель вкладок (`views/partials/navbar.hbs`) одинакова на всех трёх страницах:
лента → `/`, добавление → `/draft`, плитка → `/list` (без `id`).

Число лайков (`likesCount`) вычисляется в сервисе по `likedBy.length` и отдаётся в шаблон.

«Больше / меньше» у описания на ленте сделано на чистом HTML — нативный `<details>`,
подпись переключается через CSS `::after`. JS-кода в проекте нет.

## Запуск

```bash
npm install
npm run start:dev        # http://localhost:3000
```

Тесты:

```bash
npm run test:e2e         # проверка всех трёх страниц и фильтра
npm run lint
```

## MinIO (медиа)

Хранилище поднимается через `docker-compose.yml` (сервис `minio`): S3 API на
`:9000`, веб-консоль на `:9001`. Бакет `solution-assets` с публичным доступом на
чтение, в нём лежат фото (`HCl.PNG`, `NaOH.PNG`, …) и видео (`hcl.MP4`, `naoh.MP4`,
`nacl.mov`, …).

```bash
docker compose up -d minio
```

В модели `Solution` хранятся только **ключи** файлов (поля `image` и `video`,
латиница). Полный URL собирается в `SolutionsService.toView()`:

```
imageUrl = MEDIA_BASE_URL + '/' + solution.image
videoUrl = MEDIA_BASE_URL + '/' + solution.video
```

`MEDIA_BASE_URL` по умолчанию `http://localhost:9000/solution-assets`,
переопределяется переменной окружения. В шаблонах используется:

- `feed.hbs` — `poster="{{solution.imageUrl}}"` и `<source src="{{solution.videoUrl}}">`
- `grid.hbs` → `partials/solution-card.hbs` — `<img src="{{imageUrl}}">`
- `add.hbs` — картинка/видео не подставляются (черновик), только поля выбора файла

## Дизайн

Стилистика скопирована с **TikTok** (вертикальная лента, информация поверх видео).
Три фирменных цвета (точные коды — в шапке `public/css/style.css`):

- `#0F1117` — фон ленты
- `#4BDE81` — акцент (лайк, кнопки, иконки навигации)
- `#16181F` — подложки карточек и нижней панели

Форма карточек — скруглённые прямоугольники (`border-radius: 12px`), у элементов есть
`:hover`. Весь CSS вынесен в отдельный файл `public/css/style.css`.
